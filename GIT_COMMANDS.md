# Основные команды Git

Ниже приведены назначение команд и примеры их использования в терминале. Для работы необходим установленный Git. Команды выполняются в каталоге проекта, если не указано иное.

## 1. `git init`

Создаёт новый локальный репозиторий в текущем каталоге: Git добавляет скрытый каталог `.git` для хранения истории и настроек. Применяется для нового проекта, который ещё не является репозиторием.

```bash
cd my-project
git init
```

После `git init` удалённый репозиторий не подключается автоматически. Если проект уже получен через `git clone`, повторная инициализация не требуется.

## 2. `git clone`

Создаёт локальную копию существующего репозитория по его адресу. При клонировании Git обычно называет удалённый репозиторий `origin`.

```bash
git clone https://github.com/KirillDP/git-lab.git
cd git-lab
```

## 3. `git add`

Добавляет выбранные изменения в индекс — область подготовки следующего коммита. После редактирования файла можно подготовить его так:

```bash
git add README.MD
```

Чтобы проверить состояние файлов и индекса, можно использовать `git status`.

## 4. `git commit`

Создаёт коммит из изменений, которые уже добавлены в индекс. Флаг `-m` задаёт сообщение, кратко описывающее изменения.

```bash
git commit -m "Update README"
```

Перед первым коммитом в локальном Git при необходимости настраивают имя автора и адрес электронной почты.

## 5. `git push`

Отправляет локальные коммиты на удалённый сервер. Например, находясь в локальной ветке `git-commands`, можно отправить её в `origin` и настроить связь с удалённой веткой:

```bash
git push -u origin git-commands
```

Параметр `-u` задаёт отслеживаемую ветку; в дальнейшем обычно достаточно `git push`. Для записи на GitHub нужна авторизация и право доступа к репозиторию.

## 6. `git pull`

Получает изменения из удалённого репозитория и интегрирует их в текущую локальную ветку. Обычно интеграция выполняется слиянием, но настройка Git может задавать перебазирование. Например, чтобы обновить локальную `main` из удалённой `main`:

```bash
git switch main
git pull origin main
```

Важно: `git pull origin main` интегрирует изменения в текущую ветку и не переключает её на `main` автоматически. При конфликте изменения необходимо разрешить перед продолжением.
